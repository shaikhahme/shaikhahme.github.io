# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Personal portfolio site for Shaikh Ahmed, deployed on Vercel from the `docs/` directory (previously GitHub Pages, at https://shaikhahme.github.io/). There is no build step, package manager, or test suite — it's static HTML/CSS/vanilla JS plus a one-off Python data-prep script. Visual theme is a vintage vinyl record: black/red palette by default, grain overlay, a cursor spotlight effect, and per-section "Side A/B · Track NN" framing.

The site is four pages: a landing page, and three themed "pressings" of the same portfolio (About/Projects/Knowledge/Contact), each recolored and re-worded around a specialty — AI Alignment (green), AI Security (red, the default palette), Cybersecurity (blue). Same person, same story, three lenses.

## Architecture

- `docs/index.html` — the landing page. Wooden-crate CSS background holding three album tiles linking to the three specialty pages below; `#crateBox` and the hero copy (`#landingEyebrow`/`#landingName`/`#landingTagline`/`#landingHint`) are empty in the HTML and rendered by `initLandingContent` in `script.js` from `/data/site.json`'s `landing` key, which sets each tile's `--tile-img` (image url) and `--tile-color` (accent tint, used for the title glow/underline and as the background fallback) as inline style variables on the generated `.crate-album` anchor. No knowledge-graph libraries loaded here (nothing on this page needs them).
- `docs/ai-alignment/index.html`, `docs/ai-security/index.html`, `docs/cybersecurity/index.html` — three full copies of the portfolio page, each `<html data-theme="...">`-tagged (`green` / `red` / `blue`). None of the per-specialty prose (hero tagline, the "Why am I passionate about this?" paragraphs, Projects/Knowledge/Contact intro copy, meta title/description) is hardcoded in these files anymore — every text element that varies by specialty is an empty tag with an `id` (`heroTagline`, `passionTitle`, `passionParagraphs`, `passionCtaBtn`, `eyebrowAbout`/`eyebrowProjects`/`eyebrowKnowledge`/`eyebrowContact`, `projectsIntro`, `knowledgeIntro`, `contactIntro`, `metaDescription`, `contactEmail`/`contactEmailText`, `contactLinkedin`/`contactLinkedinText`), populated at runtime by `script.js` from `/data/pages.json` and `/data/site.json`. The projects list and testimonials are identical across all three (shared data files); the timeline is per-page (see `docs/data/timeline-*.json` below) even though all three currently hold the same placeholder milestones. Structurally each is: a centered nav (brand links back to `/`; About/Projects/Knowledge/Contact links are same-page anchors) over four anchor-linked sections (`#about`, `#projects`, `#knowledge`, `#contact`) plus a bonus `#testimonials` section. `#about` is still the two-column "front stage" it always was — `.timeline-passion` (the "Why am I passionate about this?" title/paragraphs/CTA row) paired beside `.timeline-visual-col` (the scroll-pinned vinyl), same pairing/position the original "virtue" copy held before it was renamed. No jQuery, no Cytoscape — loads `/script.js`, `/styles.css`, then (for the knowledge graph) `three.js`, `three-spritetext`, and `3d-force-graph` from unpkg, then `/app.js`.
- All four HTML pages reference shared assets via **root-relative paths** (`/styles.css`, `/script.js`, `/app.js`, `/data/*.json`) rather than relative ones, since three of the pages live one directory level down from `docs/`. This only resolves correctly when `docs/` is served as the site root (true for both the Vercel config and GitHub Pages' classic branch deploy) — don't switch these back to relative paths without accounting for the subfolder pages.
- `docs/styles.css` — all styling, shared by all four pages: crate/landing visuals, vinyl/record visuals, nav, scroll-driven About animation, project album tiles, knowledge graph layout, contact form, testimonials carousel, responsive breakpoints (stacks under 900px). Theming is CSS custom properties: `--accent`/`--accent-dim` are `var()` references onto `--molten-lava`/`--brick-ember`/`--mahogany`/`--accent-hot`, which the `:root` block sets to the red palette and `[data-theme="green"]`/`[data-theme="blue"]` blocks override — so accent-derived glows/shadows/gradients elsewhere in the file are written as `color-mix(in srgb, var(--accent) X%, transparent)` rather than hardcoded rgba, letting them re-theme automatically. Add a new specialty page by adding one more `[data-theme="..."]` block with those four variables. `body` is a `min-height: 100vh` flex column (`main` is `flex: 1 0 auto`, `footer` is `flex-shrink: 0`) — the standard sticky-footer pattern, needed so the single-viewport landing page (`.crate-hero` is `flex: 1`, no explicit height) doesn't permanently overflow by the footer's height; multi-section pages are unaffected since their content already exceeds one viewport. Landing crate tiles (`.crate-album`) no longer tilt at rest (the earlier `--tilt: -4deg/0deg/4deg` per-tile rotation made same-size tiles look uneven) — they sit flat and only lift on hover.
- `docs/script.js` — vanilla JS behavior shared by all four pages. Each `init*` function no-ops if its target DOM elements aren't present, so it's safe to include on the landing page even though most sections don't exist there:
  - Scroll-reveal (`in-view` class) for `.reveal` elements.
  - **About section**: two-column "front stage" — `.timeline-passion` (title/paragraphs/CTA row, populated from `pages.json`'s `passionTitle`/`passionParagraphs`/`passionCta`) beside the scroll-pinned vinyl (`.timeline-visual-col`), same layout the "virtue" copy held before it was renamed to "Why am I passionate about this?" and given placeholder text. As the user scrolls through `#about`, a tonearm/vinyl assembly is pinned in place and steps through the timeline (fetched from `/data/timeline-{slug}.json`, one file per specialty) — age, title, and body text update per step, along with a curved ring-title (`ringText`/`ringPath` SVG `textPath`) below the disc. The center label recolors continuously with scroll progress (`applyColor(progress)`, one hue loop per disc rotation) rather than snapping per milestone or morphing through 3D shapes. The disc sits on a small wood-crate-textured platform (`.timeline-disc` background/border) for visual separation from the page background; its drop shadow lives on a separate non-rotating `.vinyl-shadow` layer behind the disc so the shadow doesn't spin with it (`.vinyl-record` itself only keeps a rotation-invariant 1px outline).
  - **Projects section**: fetches `/data/projects.json`, sorts it so entries whose `tags` array includes the current page's slug (`ai-alignment`/`ai-security`/`cybersecurity`) come first (stable sort — everything else keeps its original relative order), then renders album-style tiles into `#projectsRow`, replacing the static placeholder tile in the HTML. Horizontal scroll row with hover lift/tilt; CSS-generated placeholder cover art (gradient + groove pattern) until real project images are supplied. "See more on GitHub" button links to `https://github.com/shaikhahme` (unconfirmed — inferred from repo naming).
  - **Testimonials**: fetches `site.json`'s `testimonials` array, renders cards into `#testimonialCarousel`, then infinite-loop auto-scrolls, pausing on hover.
  - **`initSpecialtyContent`** (specialty pages only, gated on `#heroTagline`/`#passionParagraphs` existing): derives the page slug from `location.pathname`, fetches `/data/pages.json` and `/data/site.json`, and fills in every per-specialty text node plus the shared contact email/LinkedIn line. The About/hero eyebrow uses each page's own `heroTrack` ("01"/"02"/"03") from `pages.json`; the Projects/Knowledge/Contact eyebrows are built in JS from `specialtyLabel` with fixed Track 02/03/04 (Side A for About/Projects, Side B for Knowledge/Contact) since that sequence is identical across pages.
  - **`initLandingContent`** (landing page only, gated on `#crateBox`): fetches `site.json`'s `landing` key and renders the hero copy plus the three crate tiles (title, description, `--tile-color`, `--tile-img`) into `#crateBox`.
  - Cursor spotlight glow, nav active-section indicator (both work generically, no page-specific handling needed).
- `docs/app.js` — renders an interactive **3D** knowledge-graph visualization in `#knowledge` (on the three specialty pages only) using `3d-force-graph` (Three.js-based, not Cytoscape), fetching `/data/graph.json` into the `#cy` canvas. Drag to rotate, scroll to zoom, click a node for details (shown in the `.graph-sidebar`). Camera start distance scales with node count and label visibility scales per-node by rank — `nodeRelSize` is still a flat constant. After the initial overview framing, each specialty page eases the camera onto its own anchor node (`ANCHOR_LABELS`: `ai-alignment`→"AI Alignment", `ai-security`→"AI Security", `cybersecurity`→"Cybersecurity") once the force layout has had ~1.2s to cluster, and populates the sidebar with that node's info — same node-lookup approach as `onNodeClick`.
- `docs/data/topics.json` — source list of knowledge-base topics, each with `label`, `desc` (short), `longDesc` (used for similarity), and `rank` (drives node size). Shared across all three specialty pages. Includes placeholder topics `"AI Alignment"` and `"AI Security"` (`"placeholder": true`) added as anchor targets for those two pages — `"Cybersecurity"` already existed as a real topic and serves as that page's anchor without needing a placeholder.
- `docs/data/graph.json` — generated force-graph elements (`nodes`/`edges`) consumed by `app.js`. Regenerate it from `topics.json` rather than hand-editing (see `scripts/generate-gk-script.py` below — note its `scikit-learn` dependency wasn't installable in the sandbox this session, so the current file was produced by a hand-rolled TF-IDF/cosine-similarity script replicating sklearn's default `TfidfVectorizer` formula; results should closely match what the real script produces, but re-run the real script next time it's available to be exact).
- `docs/data/timeline-ai-alignment.json`, `docs/data/timeline-ai-security.json`, `docs/data/timeline-cybersecurity.json` — per-specialty About-section milestones (`age`, `title`, `text`) driving the scroll-pinned vinyl animation, fetched by `initTimeline` based on the page's slug. Currently hold identical placeholder content (copied from the old shared file) — edit each independently now that the split exists. There is no longer a single shared `timeline.json`.
- `docs/data/projects.json` — Projects-section entries (`name`, `description`, `link`, `image`, `tags`); `image` is currently empty for all entries (placeholder art used instead). `tags` is an array of page slugs (`ai-alignment`/`ai-security`/`cybersecurity`) used to sort each specialty page's project row so its most relevant work surfaces first — assigned by inference from each project's description, not by the user, so double-check/adjust if a project's real-world relevance differs. Shared (same entries, same data) across all three pages; only the render order differs per page.
- `docs/data/pages.json` — per-specialty prose, keyed by page slug (`ai-alignment`/`ai-security`/`cybersecurity`): `metaTitle`, `metaDescription`, `specialtyLabel`, `heroTrack` (page-level "Track 01/02/03" shown only in the About/hero eyebrow), `tagline`, `passionTitle`, `passionParagraphs` (array), `passionCta`, `projectsIntro`, `knowledgeIntro`, `contactIntro`. `passionTitle`/`passionParagraphs`/`passionCta` currently hold generic placeholder copy ("Why am I passionate about this?" + a one-line placeholder per specialty) — the real personal reasoning that used to live in the About section's "virtue" paragraphs was replaced with this placeholder by request; fill in real copy here whenever ready. This file is the single source of truth for all of this copy — the HTML no longer carries a duplicate fallback, so editing only this file is sufficient. Fetched and applied by `initSpecialtyContent` in `script.js`.
- `docs/data/site.json` — content shared across all pages: `contact` (email, LinkedIn URL/label), `testimonials` (array of `quote`/`credit`, fed to the testimonials carousel), and `landing` (the landing page's hero eyebrow/name/tagline/hint plus its `tiles` array — `page`, `title`, `description`, `color`, `image` — one entry per crate album). Fetched by `initTestimonials` and `initLandingContent`/`initSpecialtyContent` in `script.js`.
- `scripts/generate-gk-script.py` — builds `docs/data/graph.json` from `docs/data/topics.json`: TF-IDF vectorizes each topic's `longDesc`, computes pairwise cosine similarity, and adds an edge between two topics when similarity exceeds `0.2`. Requires `scikit-learn`. Run from the repo root:
  ```
  python scripts/generate-gk-script.py
  ```
  This is still the plain data-prep script described below under "Planned: Knowledge Agent" — it has not yet been reworked into an agent.
- The Contact form (present on each specialty page, all pointing at the same endpoint) POSTs to a Google Apps Script endpoint — external integration, not part of this repo's code.

## Working in this repo

- Changes to `docs/` deploy automatically via Vercel on push to `main` — there is no CI/build pipeline to run first. The repo has no `vercel.json`; Vercel project settings (root/output directory pointed at `docs/`) live in the Vercel dashboard, not in-repo.
- There used to be a GitHub Actions workflow (`static.yml`) deploying to GitHub Pages; it's been removed now that Vercel is the deploy target. If GitHub Pages is still enabled in the repo settings, disable it there to avoid two live copies of the site — that's a dashboard setting, not something fixable from this repo.
- When editing knowledge-base topics, update `topics.json` and regenerate `graph.json` with the script above rather than editing the generated file directly. `.github/workflows/generate-graph-json.yml` also does this automatically on a weekly cron and on pushes to `topics.json` or the script itself — this workflow is unrelated to deployment and still runs.
- Bump the `?v=N` query param on the `styles.css`/`script.js`/`app.js` `<script>`/`<link>` tags **in all four HTML pages** when shipping changes to those shared files, for cache-busting — they must all carry the same version number or pages will disagree on which copy they're using.
- When editing the timeline, projects, knowledge-graph content, or any visible page prose (hero tagline, the "Why am I passionate about this?" paragraphs, section intros, meta description, testimonials, landing tile copy, contact info), edit it in `docs/data/` (`timeline-{slug}.json`, `projects.json`, `topics.json`/`graph.json`, `pages.json`, `site.json`) — none of that text lives in the HTML anymore, so editing JSON alone is sufficient; no HTML or `script.js` change needed for a copy-only edit. Only touch the HTML directly for structural changes (new sections, new fields, markup/behavior changes). The timeline is now per-page (`timeline-ai-alignment.json` etc.) rather than one shared file — edit the one for the specialty you mean to change.

Their `longDesc` is written to produce plausible similarity edges (to Machine Learning, NLP, Application Security, etc.) but is otherwise placeholder text — flesh these out into real topics (or replace them) whenever the knowledge base actually covers that ground, and re-run the regeneration script.

Results should be very close to what the real script would produce, but re-run the real script (or verify sklearn is available) next time `topics.json` changes, rather than assuming the hand-rolled version stays in sync.

Tags were assigned by inference from each project's name/description, not confirmed by the user — spot-check them, especially any project that's genuinely relevant to more than one specialty.
