# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Personal portfolio site for Shaikh Ahmed ("Shaikh's Virtues"), deployed on Vercel from the `docs/` directory. There is no build step, package manager, or test suite — it's static HTML/CSS/vanilla JS, plus Three.js and GSAP pulled in from CDNs.

It's a single page: a scroll-driven, typewriter-on-lined-paper animation that builds a 3D "compass" (four axis labels — Engineering, Cybersecurity, Sociology and Psychology, Artificial Intelligence — drawn as arrows out from a center "Shaikh's Virtues" label) which folds into an interactive sphere carrying six more concept-vector labels (AI Alignment, AI Security, Security Architecture, Social Engineering, Neural Networks, AI Governance). Once formed, the sphere is drag-to-rotate/pinch-to-zoom. Clicking any label — including the center one — zooms out of the sphere and zooms into a full-page DOM overlay, Prezi-style, anchored at the click point.

`design.md` is the running spec for this page (written in phases, typos and all — it's the user's own working notes, not polished prose). Treat it as the current backlog/source of truth and keep it updated as phases land, rather than re-deriving intent from the code alone.

## Architecture

- `docs/index.html` — the only page. Loads GSAP + ScrollTrigger from cdnjs, Three.js (`OrbitControls`, `CSS2DRenderer`) via an import map from unpkg, then `zoom-anim.js`, `relevant-page.js`, and `continuous.js` (as a module) in that order. `#paperBg` is the fixed, negative-stacked ruled-paper background layer (lined paper + red margin rule, "Special Elite" typewriter font from Google Fonts) — deliberately not `background-attachment: fixed` on `body` itself, since that fights the WebGL canvas repainting every scroll frame and visibly flickers. `#stage` holds `#webgl` (the Three.js renderer) and `#css2d` (`CSS2DRenderer` labels) — the compass/sphere scene. `#spacer` is a `550vh` scroll driver for the GSAP `ScrollTrigger`-scrubbed timeline in `continuous.js`.
- `docs/continuous.js` — the scene and its scroll-scrubbed timeline. Builds the center label, the four compass axes (arrow + typewriter label each), the circle joining the arrow tips, two perpendicular great-circle equators, the sphere + wireframe mesh it becomes, and the six concept vectors. All of this is driven by one GSAP timeline scrubbed against page scroll (`onUpdate` toggles the scroll cue and hands control to `OrbitControls` once the concept vectors start revealing). Pinch-to-zoom is hijacked from `wheel` events with `ctrlKey` (the browser's native pinch-zoom convention) rather than `OrbitControls`' built-in zoom, so plain scroll/trackpad wheel is left free to always drive the timeline. Clicking a fully-typed, fully-visible label (`onLabelActivate`) zooms the stage out and hands off to `relevant-page.js`'s `renderRelevantPage` inside a `.zoom-page` overlay — the center label is distinguished from the other nine purely by its `center-label` CSS class, not by matching its text.
- `docs/relevant-page.js` — renders what a label's overlay zooms into, in one of two modes:
  - **Any axis/concept label**: title + a placeholder note (`Placeholder note for ${label} - ...`, hardcoded in this file — there's no real per-topic prose yet) + a "Projects" heading + a scrollable `.projects-list`, fetched from `/data/projects.json` and filtered to entries whose `tags` include that label (`RELEVANT_PAGE_ALIASES` handles the one spelling mismatch: the axis is "Artificial Intelligence", the tag is "AI"). Clicking a project slides in a right-hand `.mindmap-sidebar` that plays a **timer-driven** (not scroll-linked) animated mind-map of that project's `mindmap` steps: shape + border color by `type` (`arbitrary`/`decision` → black rectangle/diamond, `ai` → red rectangle, `output` → green rectangle), typewriter title/description, an arrow growing in between steps.
  - **The center "Shaikh's Virtues" label**: skips the Projects section entirely: the sidebar opens itself (no click needed) and loops the same mind-map animation forever using `/data/timeline.json` (one milestone per `arbitrary`/black-rectangle step — age + title as the box's title, the milestone text as its description), restarting from step 1 each time it finishes.
  - Both the project list and the mind-map flow are independently-scrolling regions under a pinned header (title/note/heading; project name/description/link) — the page itself never scrolls — and each paints its own ruled-line background with `background-attachment: local` so the lines scroll with the text instead of staying pinned to the (non-scrolling) viewport-fixed background on `.zoom-page`.
- `docs/zoom-anim.js` — one shared rAF-driven scale/opacity tween (`zoomAnimate`), used for both the compass-stage zoom-out/in and the overlay's zoom-in/out. CSS `transition` on transform/opacity was found not to advance reliably in some tested environments (gets stuck at its start value even though the class change registers) — this project drives essentially all of its motion (this tween, the sidebar slide, the typewriter character reveal, the arrow-grow) from `requestAnimationFrame` instead, for the same reason.
- `docs/styles.css` — the one stylesheet: ruled-paper/typewriter visual language, the `.zoom-page` overlay, the relevant-page layout, the mind-map sidebar, responsive stacking under 720px. CSS custom properties in `:root` (`--paper`, `--rule-blue`, `--margin-red`, `--ink`, `--ink-dim`, `--accent`) drive the palette.
- `docs/data/projects.json` — 17 real projects, each `{name, description, link, tags: [...], mindmap: [{step, type, title, description}, ...]}`. `tags` were assigned/confirmed by the user directly (a phase-4 GitHub interview walkthrough — see `design.md` and `updates.md`), not inferred.
- `docs/data/timeline.json` — Shaikh's life timeline, `[{age, title, text}, ...]`, read only by the center label's auto-playing sidebar.
- `updates.md` — the user's own personal TODO notes on individual GitHub repos (renames, READMEs, longer-term feature work) gathered during that same phase-4 interview. Not read by any code; keep it as-is unless asked to edit it.

## Working in this repo

- No build step, package manager, or test suite. Everything is loaded directly by `docs/index.html` — CDN/unpkg for Three.js and GSAP, local files for everything else.
- Changes to `docs/` deploy automatically via Vercel on push to `main`. The repo has no `vercel.json`; Vercel project settings (root/output directory pointed at `docs/`) live in the Vercel dashboard, not in-repo.
- Bump the `?v=N` query param on the `styles.css`/`zoom-anim.js`/`relevant-page.js`/`continuous.js` `<script>`/`<link>` tags in `docs/index.html` when shipping changes to those files, for cache-busting.
- Editing project/mind-map content is a JSON-only edit (`docs/data/projects.json`); editing the life timeline is a JSON-only edit (`docs/data/timeline.json`). Only touch the JS/HTML/CSS directly for structural or behavioral changes.
- The per-topic "note" copy is not in a data file yet — it's the hardcoded placeholder string in `renderRelevantPage` (`docs/relevant-page.js`). Real per-topic prose, if/when it exists, should probably move into its own data file rather than staying hardcoded.

## History

This used to be a four-page portfolio (a landing page plus three recolored "AI Alignment"/"AI Security"/"Cybersecurity" specialty pages, each with an About/Projects/3D-knowledge-graph/Contact layout, vinyl-record theming, a Python TF-IDF script generating the knowledge graph, and a weekly GitHub Action to regenerate it). All of that — `docs/ai-alignment/`, `docs/ai-security/`, `docs/cybersecurity/`, the old `docs/index.html`/`script.js`/`app.js`/`styles.css`, `docs/images/`, `docs/data/{pages,site,graph,topics}.json`, `scripts/generate-gk-script.py`, and `.github/workflows/generate-graph-json.yml` — was deleted once the scroll-animation page (`design.md`'s "shk-vis") became the only thing this site needed to be; that page was then promoted from `docs/prototypes/` to the site root (dropping the `/prototypes/` path segment and the "shared"/prototype naming, e.g. `shared.css` → `styles.css`). If you find a reference to any of the deleted structure elsewhere (old commits, external links, memory from a prior session), treat it as stale.
